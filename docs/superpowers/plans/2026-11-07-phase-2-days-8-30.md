## Global Constraints

Everything in the Phase 1 plan's Global Constraints still applies. In short:

- Python 3.13, `temporalio>=1.34`, `uv`. Load the `temporal-developer` skill before writing Temporal code. Verify SDK APIs against it, against docs.temporal.io, or by running them. Never rely on memory.
- Blocking libraries go in `def` activities. Every worker uses `ThreadPoolExecutor(max_workers=10)` with `max_concurrent_activities=10`, and `tests/test_worker.py` stays green each day.
- Lesson sections, exactly: `## Why today matters`, `## Concept`, `## Walkthrough`, `## Run it`, `## Break it`, `## Check yourself` (answers in `<details>`), `## Solution`. Keep the prev/next nav line under the H1.

- Each solution's tests pass with `LAB_MODE=mock` and no lab. Tests that need a real dev server (schedules, search attributes, Nexus, worker versioning) use `WorkflowEnvironment.start_local()`. That downloads the dev server once, and CI may do the same.

- **AI week uses GitHub Copilot models through GitHub Models**: OpenAI-compatible base URL `https://models.github.ai/inference`, token in `GITHUB_TOKEN`, model in `LLM_MODEL`. ## Locked decisions

- **Branch:** `phase-2-days-8-30` from `main`.
- **Compliance policy:** `netops_temporal/policies.py`, `POLICIES: dict[str, list[str]]` keyed by Nautobot role (`router`, `access`). Both roles require `ntp server 192.0.2.10`; routers also require `logging host 192.0.2.50`. - **Default LLM model:** `openai/gpt-4.1-mini`, unless the build-time check shows a better default on GitHub Models. Record that as a ruling.

## Review Focus

1. **A signal, update or query that arrives while continue-as-new is happening** (Days 12–14). Expected: no lost signals, and updates either finish or get re-sent. Covered by `test_signal_during_continue_as_new_not_lost` (Task 5) and `test_entity_handlers_finish_before_can` (Task 6).
2. **Duplicate remediation**: drift is seen again while a remediation is still running. Expected: no second workflow. Covered by `test_duplicate_drift_reuses_running_remediation` (Task 9).
3. **Saga cancellation mid-push**: an operator cancels after the push but before verification. Expected: rollback still runs, and the workflow ends Canceled. Covered by `test_cancel_after_push_rolls_back` (Task 10).
4. **The LLM returns malformed or off-schema JSON.** Expected: the attempt fails and is retried. It is never passed on as a half-parsed model. Covered by `test_malformed_llm_json_is_retryable` (Task 18).
5. **The agent tries a config-changing command through a tool** (`configure`, `write`, `reload`, a `|` pipe to bash). Expected: the guardrail rejects it before any device call. Covered by `test_show_tool_rejects_non_show_commands` (Task 19) and `test_mcp_tool_rejects_config_commands` (Task 21).

## How every day-task runs

Each Task N for a day follows the same skeleton. The task lists only what's specific to it.

1. `cp -r solutions/day-(NN-1) solutions/day-NN` (drop `__pycache__`).
2. Write the listed failing tests in `solutions/day-NN/tests/`. Run them with `scripts/test-solutions.sh NN` and expect FAIL for the stated reason.
3. Implement the listed code. Register any new workflows and activities in `workers/main.py`'s `WORKFLOWS`/`ACTIVITIES` lists.
4. Run `scripts/test-solutions.sh NN`. Expect all tests to pass, including the previous day's tests carried over.
5. **Live check** (if the task says "Live"): run the worker and starter through `scripts/solution.sh NN …` against the lab through the tunnels. Record the outcome in the ledger.
6. **History** (if the task says "History"): export a real run with `tools/export_history.py` into `tests/histories/`, and add it to the replay test.
7. Rewrite `days/<week>/day-NN-*/README.md` in the Phase 1 format. `# file:` snippets come from the solution. Every "Break it" item must have actually been run (in mock mode, or live if marked), and its described result must match what was observed.
8. Run `uv run python scripts/check_lessons.py days/<week>/day-NN-*/README.md`. Expect `OK`.
9. Commit with the message `day NN: <topic>`.

**Files:** Create `workflows/watch.py`, `starters/watch.py`. Modify `models.py`, `workers/main.py`. Test `tests/test_watch.py`.

**Interfaces:**
- Produces:
  - `WatchRequest(device: str, interval_seconds: int = 300)`.
  - `DeviceWatchWorkflow.run(req: WatchRequest) -> None` (loops forever).
  - Signals `pause()`, `resume()` and `check_now()`, all returning `None`.
  - State attributes `paused: bool`, `checks: int`, `last_facts: DeviceFacts | None`.
  - Each loop: `wait_condition(not paused)` → `get_device_facts` → `checks += 1` → `wait_condition(check_requested, timeout=interval)`, with the `asyncio.TimeoutError` caught.
  - Starter: `python -m netops_temporal.starters.watch <device> [start|pause|resume|check-now]`.
- [ ] Tests (time-skipping env, mock lab):
  - `test_watch_runs_check_on_start`: after start plus a short time-skip, the history has 1 `ActivityTaskCompleted`.
  - `test_check_now_signal_triggers_extra_check`: signal `check_now` → 2 completed activities without the interval elapsing.
  - `test_pause_stops_checks`: `pause` then skip 3 intervals → the count doesn't change; `resume` → it increases.
- [ ] Lesson notes:
  - Concept: a signal is a fire-and-forget message written into history (network analogy: an SNMP trap into the change ticket), and `wait_condition`.
  - Break it: signal while the worker is stopped (it's delivered on restart); signal a workflow ID that doesn't exist (`NotFoundError`); remove the `await` from `wait_condition` (the warning or failure you observe). Live.
